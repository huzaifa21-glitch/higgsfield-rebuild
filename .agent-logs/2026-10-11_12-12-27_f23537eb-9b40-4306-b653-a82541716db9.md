I've fixed it. The problem was the rewrite rule in `vercel.json`, not `index.html`. Under `vercel dev` the rule sent Vite's own requests to the app's HTML page: `/src/main.tsx`, `/@vite/client` and even `/favicon.svg` all came back as HTML. The browser then loaded that HTML as JavaScript, and Vite failed to parse it, which gave your error. In production Vercel serves real files before applying rewrites, so this only broke locally. My earlier check passed because I only tested the rule's pattern and didn't run it under `vercel dev`.

The new rule in `vercel.json`:

```json
{ "source": "/((?!api/|@)[^.]*)", "destination": "/index.html" }
```

Only paths with no file extension that don't start with `api/` or `@` (Vite's internal paths) go to the app. Your running `vercel dev` picks this up without a restart; just reload the page. I tested it with a second `vercel dev` on port 3100 (now stopped):

| Path | Before | After |
|---|---|---|
| `/`, `/library`, `/library/abc`, `/nope` | app page | app page ✅ |
| `/src/main.tsx` | HTML ❌ | `text/javascript` ✅ |
| `/@vite/client` | HTML ❌ | `text/javascript` ✅ |
| `/favicon.svg` | HTML ❌ | `image/svg+xml` ✅ |
| `/api/health` | `{"ok":true}` | `{"ok":true}` ✅ |
| `/api/jobs` | — | `501 Not implemented` ✅ |

- **Dots in app URLs:** an app URL containing a dot, like `/library/photo.png`, won't reach the app any more and will return Vercel's 404. That's fine as long as Library item URLs use IDs.
- **Missing `provider` field:** `/api/health` returns no `provider` because `IMAGE_PROVIDER` isn't set anywhere yet. Add `IMAGE_PROVIDER=cloudflare` to `.env.local` for local runs, and set it in the Vercel project for deploys.
